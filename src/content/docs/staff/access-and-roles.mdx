# Доступ, Auth и роли

## Добавление нового игрока

Сначала модерация принимает решение о доступе. Затем добавь игрока в whitelist и сообщи ему только официальную инструкцию/адрес. Не выдавай OP, временную роль модератора или пароль от чужого аккаунта ради «быстрого входа».

### Vanilla whitelist

```text
/whitelist add <ник>
/whitelist remove <ник>
/whitelist list
/whitelist reload
/whitelist on
/whitelist off
```

`add` допускает игрока; `remove` снимает доступ; `list` показывает текущий список; `reload` перечитывает whitelist после ручного изменения файла. `on/off` меняет глобальное состояние — эту пару использует только администратор в исключительной ситуации, а не модератор во время стрима.

Пример:

```text
/whitelist add ExamplePlayer
```

После добавления попроси игрока войти под тем же ником, который был одобрен. Если EasyWhitelist меняет способ ведения списка, проверяй результат командой `/whitelist list`, а не редактируй UUID-файлы вручную на работающем сервере.

## EasyAuth

EasyAuth защищает сервер до входа: неавторизованный игрок не должен двигаться, строить, использовать предметы и выполнять обычные команды.

### Команды игрока

```text
/register <пароль> <пароль>
/reg <пароль> <пароль>
/login <пароль>
/l <пароль>
/logout
/account unregister <пароль>
/account changePassword <старый_пароль> <новый_пароль>
/account online <пароль> [confirm]
```

- `register`/`reg` создаёт пароль для первого входа.
- `login`/`l` авторизует в текущую сессию.
- `logout` завершает сессию вручную.
- `account unregister` удаляет собственную запись — перед этим игрок должен понимать последствия.
- `account changePassword` меняет пароль; модератор никогда не просит прислать оба пароля в сообщении.
- `account online` относится к отметке аккаунта как online/Mojang-аккаунта; не советуй её использовать без необходимости и инструкции администрации.

### Админ-команды EasyAuth

```text
/auth reload
/auth setGlobalPassword <пароль>
/auth setSpawn [<dimension> <x> <y> <z> <yaw> <pitch>]
/auth remove <ник>
/auth update <ник> <новый_пароль>
/auth register <ник> <пароль>
/auth list
/auth getPlayerInfo <ник>
/auth getOnlinePlayers
/auth markAsOffline <ник>
/auth markAsOnline <ник>
```

`reload` перечитывает конфиг. `setSpawn` меняет временную точку, куда попадает игрок до авторизации; выполняй её только после согласования, поскольку неверные координаты могут запереть всех новых игроков. `remove`, `update` и `register` изменяют учётную запись: применяй только после проверки личности через согласованный канал. `setGlobalPassword` — аварийная серверная настройка, не инструмент для обычной модерации.

## LuckPerms

LuckPerms управляет группами и точечными правами. Работай через группы, а не через ручную выдачу десятков узлов одному нику.

```text
/lp user <ник> parent add <группа>
/lp user <ник> parent remove <группа>
/lp user <ник> parent info
/lp user <ник> permission set <узел> true
/lp user <ник> permission unset <узел>
/lp group <группа> permission set <узел> true
/lp group <группа> permission unset <узел>
/lp groups list
/lp editor
/lp verbose on
/lp verbose off
/lp sync
```

Примеры:

```text
/lp user ExampleModerator parent add moderator
/lp user ExampleModerator parent remove moderator
/lp user ExamplePlayer permission set example.permission true
```

`editor` открывает веб-редактор LuckPerms: используй его для большой перестройки ролей, затем применяй сгенерированную команду и фиксируй ссылку/изменение в журнале команды. `verbose` временно показывает проверки прав и полезен при диагностике; после проверки выключай. `sync` нужен, если сервер настроен на внешнее хранилище — не используй его как «кнопку починки» без понимания настроек.

## OP — только для владельца/админа

```text
/op <ник>
/deop <ник>
```

OP обходит нормальную модель прав и способен сделать почти всё. Обычному модератору OP не выдаётся. Если временный OP действительно необходим, запиши причину, время выдачи и выполни `/deop <ник>` сразу после операции.
